# 论文总结模板（用户确认版 v1）

> 用途：每日论文展示网页中每篇论文的总结字段规范。回答必须专业正确。
> 来源：用户 2026-08-27 提供。

## 标准总结模板

**0. Background**（精简一句话）
- 作者所属科研单位/高校、被引次数、收录会议、发表时间、代码是否开源、GitHub star

**1. Task**（1-2 句）
- 这篇文章解决的核心 Task 是什么？解决了什么 challenge（围绕论文解决了的 technical challenge 展开）

**2. Insight**（1-2 句）
- 作者的 insight 受到了什么启发？

**3. Pipeline**
- 3.1 Input & Output（精简）
- 3.2 流程图（文字版，结构简洁，梳理好每一个模块）

**4. Methods**（按实际论文的 method 逐个介绍）
- pipeline 中的重点模块、采用的新方法、loss 的设计等

**5. Experiment**（精简几句话）
- 使用了哪些数据集、效果怎么样、做了哪些消融实验

**6. Limitation**（精简几句话）
- 作者自己承认的失败情形，或从实验中能看出的潜在问题

## 问答规则

- 当用户询问论文相关问题时，根据论文内容回答，**必须提及涉及论文的哪一部分**。

## 笔记版本（仅当用户明确要求"笔记版本"时启用）

1. 公式：用 LaTeX 代码表示（不渲染），公式不单独分行
2. 变量表示：数字、符号使用代码格式
3. 排版：注意各级标题使用，一个大模块一个分割线
4. 不要有额外的排版符号（竖线、点等）

## 筛选规则（用户确认版 v1，2026-08-27 放宽）

**旧论文（2025 年前）**：
- 被引次数 ≥ 15 或 GitHub star ≥ 100 -> 入选候选
- 顶会（CVPR/ICCV/ECCV/NeurIPS/ICLR/SIGGRAPH）oral/spotlight 优先
- 经典奠基工作单独标记「经典」标签

**新论文（2025 年及以后）**：
- 作者影响力：知名机构/学者加分
- HF upvote ≥ 30 加分；有关联 GitHub 仓库加分
- LLM 相关性打分（三维重建/世界模型方向）≥ 阈值才入选

**偏好反馈闭环**：
- 用户每日审阅标注「喜欢/不喜欢 + 原因」，逐周迭代筛选关键词与权重
